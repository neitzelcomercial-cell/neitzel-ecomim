VISÃO GERAL
O ECOMIM deve deixar de ser apenas um CRM e se tornar uma central operacional completa do negócio.
O usuário deve conseguir controlar o negócio integralmente através de uma única plataforma.
Fluxo Integrado:
CLIENTES → AGENDA → SERVIÇOS → PRODUTOS → ESTOQUE → VENDAS → DESPESAS → LUCRO
Importante: Não recrie o ECOMIM, não remova funcionalidades, não quebre o que existe. Reutilize a
arquitetura, banco, autenticação, componentes e regras existentes. Prioridade: funcionalidades
REALMENTE funcionais, conectadas ao banco de dados e entre si.

6. ESTOQUE
Criar controle real de estoque com rastreamento de todas as movimentações.
Tipos de Movimentação:
 Entrada — Compra/recebimento de produtos
 Saída — Venda ou descarte
 Ajuste — Correção de inventário
 Venda — Produto vendido para cliente
 Utilizado em serviço — Produto usado em atendimento
Cada Movimentação Registra:
✓ Produto — Qual produto
✓ Quantidade — Quanto movimentado
✓ Tipo — Tipo de movimentação
✓ Data — Quando aconteceu
✓ Usuário — Quem realizou

✓ Referência relacionada — Link a venda, serviço, etc
Automação: Quando um serviço é realizado, os produtos utilizados devem diminuir automaticamente do
estoque. Quando um produto é vendido, o estoque também diminui automaticamente.

14. CÁLCULO DE LUCRO
Criar cálculo automático e visível de todas as métricas de lucratividade.
Métricas Calculadas Automaticamente:
✓ Receita bruta — Total de receitas
✓ Custo dos produtos — COGS
✓ Custo dos serviços — Custo de realização
✓ Despesas — Gastos operacionais
✓ Lucro bruto — Receita - Custos
✓ Lucro líquido — Receita - Custos - Despesas
✓ Margem de lucro — Percentual de lucro
Fórmula Principal:
 RECEITA - CUSTOS - DESPESAS = LUCRO LÍQUIDO
Exibir os números claramente em dashboards e relatórios.

25. REGRAS IMPORTANTES
✓ Dados Reais: Não criar dados fictícios. Tudo deve ser real.
✓ Conexão DB: Não criar telas que não estejam conectadas ao banco.
✓ Backend Completo: Não implementar apenas frontend.
✓ Persistência: Toda ação importante precisa persistir corretamente.
✓ Transações: Atualizações de estoque precisam ser transacionais.
✓ Precisão: Valores financeiros precisam usar precisão adequada.
✓ Sem Duplicação: Evitar duplicidade de registros.
✓ Histórico: Registrar histórico de alterações importantes.
✓ Permissões: Respeitar autenticação e permissões do usuário.
